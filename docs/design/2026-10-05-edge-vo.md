# The edge VO pipeline (milestone 2, PR 8)

Milestone 2's second slice: ORB-SLAM-lite in `slamlab.edge`, monocular, stereo and RGB-D, in
Python, C++ and Rust in lock-step, plus native programs that run a whole sequence. Decided
with evan-wes on 2026-10-05: stage-level parity with whole-sequence agreement by ATE; native
executables in this PR; a lost track ends the run; one PR; synthetic fixtures; results on
TUM and EuRoC without a hard ATE gate; `SlamInput`/`SlamResult` wait for milestone 3. The
ladder's design doc ([2026-10-02-slamlab-ladder.md](2026-10-02-slamlab-ladder.md)) records
where this sits; this note is the PR's plan.

## 1. What the pipeline does (ORB-SLAM-lite)

Per frame, for every mode:

1. **Extract** ORB (rung 0). Stereo: rectify (maps computed once), extract both views,
   match along rows (`stereo.match`); RGB-D: each keypoint's depth from the depth map. Both
   give a keypoint a depth and a virtual right column `u_r = u - f b / z` (RGB-D uses a
   virtual baseline, as ORB-SLAM does), so stereo and RGB-D share everything after this.
2. **Initialise**, until a map exists:
   - monocular: two-view (`twoview.initialize`) between a reference frame and the current
     one; on `low_parallax` or `ambiguous`, keep the reference and try the next frame; after
     a set number of failures, take the current frame as the new reference (ORB-SLAM's
     retry). The map's scale is the initial baseline's (median depth 1), as in ORB-SLAM.
   - stereo and RGB-D: the first frame with enough keypoints that have depth becomes the first
     keyframe, its points created from depth: metric from the start.
3. **Track**:
   - predict the pose with a constant-velocity model (last motion applied again);
   - match the last frame's map points by projection into a window around the prediction
     (guided matching, below); if too few match, widen the window and retry;
   - refine the pose, motion only (`pnp.refine_pose`, robust, with outlier rejection rounds,
     ORB-SLAM's chi-square thresholds 5.991 mono and 7.815 stereo);
   - track the local map: project the points of the local keyframes (the window, below) not
     yet matched, match them, refine again;
   - **fallback:** if the prediction fails (too few inliers), PnP RANSAC (rung 0) against the
     local map's points matched by descriptor; if that fails for a few frames with a widened
     search, the track is lost and the run ends there (recorded in the diagnostics).
4. **Decide on a keyframe** with ORB-SLAM's tests: enough frames since the last one, or the
   tracked points fell below 90% of the reference keyframe's (with a minimum of inliers);
   stereo and RGB-D also when too few close points are tracked.
5. **Map locally** after each new keyframe:
   - stereo and RGB-D: create the new keyframe's close points from depth;
   - triangulate new points between the new keyframe and the window's other keyframes
     (descriptor matches checked against the epipolar constraint, parallax, reprojection
     and scale consistency, as ORB-SLAM's `CreateNewMapPoints`);
   - fuse duplicates (a point matched to one already in the map);
   - local BA (`foundations.ba`) over the window's keyframes and their points, the keyframes
     just outside it fixed, robust loss;
   - cull points (found in under 25% of the frames that should have seen them, or seen by
     fewer than 2 (mono) / 3 (stereo, RGB-D) keyframes two keyframes after creation) and
     keyframes (90% of whose points three other keyframes see at the same or a finer scale).

**Lite**, against ORB-SLAM: a **sliding window of the last N keyframes** (N = 10 default)
stands in for the covisibility graph; **no bag of words** (no relocalisation, no loop
closure, no place recognition: the classic rung's, milestone 4); **one thread** (mapping
runs after tracking on a keyframe, in sequence, so a run is deterministic); **no map reuse**.

## 2. Modules

### Rung 0 additions (`slamlab.foundations`, three languages)

- `matching.search_by_projection(projected, radius, levels, frame_features, ...)`: for each
  projected map point, the best frame keypoint within the radius at a compatible level, by
  Hamming distance with ORB-SLAM's thresholds and ratio test; one map point per keypoint
  (A10). With a per-frame **feature grid** (`matching.FeatureGrid`, cells of 64 x 48 px, as
  ORB-SLAM's `GetFeaturesInArea`), so a search is local, not brute force.
- `image.level_coordinate(u, level_size, size)`: the full-image-to-level map, the inverse of
  `full_image_coordinate` (A17); stereo's level-to-level column is restated through the two.
- `homography`: H-RANSAC refuses a fitted H of rank below 3 (the open "non-invertible H"
  item), so two-view's rank-1 workaround becomes the estimator's own rule.

### The edge rung (`slamlab.edge`, `slamlab_edge`, `slamlab-edge`)

The state is a struct of arrays in all three languages, so stage functions cross the
bindings as dicts of arrays, like rung 0's:

- `edge.map`: `Map`: keyframes (poses `T_cam_world`, their features, timestamps), points
  (positions, a reference descriptor, the normal and distance range for the scale check,
  visible and found counts), observations (keyframe, point, keypoint). Operations: add a
  keyframe, add or fuse points, erase culled ones, the window's local map.
- `edge.frames`: `Frame`: one input frame's features, per-keypoint depth and right column
  (stereo, RGB-D), and its pose once tracked; built from the images by mode.
- `edge.tracking`: `initialize_monocular`, `initialize_from_depth`, `predict`,
  `track_last_frame`, `track_local_map`, `relocalize_locally` (the PnP fallback), each a
  function of explicit state (stage parity).
- `edge.mapping`: `need_keyframe`, `create_points_from_depth`, `triangulate_new_points`,
  `fuse_points`, `local_bundle_adjustment`, `cull_points`, `cull_keyframes`.
- `edge.pipeline`: `Pipeline(mode, camera, options)` with `track(frame) -> FrameResult`
  (pose or lost, tracked points, timings), holding the map; the per-frame loop of section 1
  over the stage functions. Python's runs in-process; C++ and Rust's run in the native
  programs (below), not across the binding.
- `edge.Options`: every threshold above, named and defaulted to ORB-SLAM's, crossing as a
  dict.

### Native programs (decision B)

- **Where.** A run needs the edge rung and `eval` (readers and the run writer), so the
  programs sit above both, in orchestration: C++ `cpp/apps/slamlab_vo.cpp` (library
  `slamlab_orchestration`), Rust crate `slamlab-vo` (a binary). The design doc's
  Package-layout table gives orchestration C++ and Rust rows; `check_layers.py` holds them
  to the ladder.
- **What they do.** `slamlab_vo --dataset tum|euroc --sequence PATH --mode
  mono|stereo|rgbd --out RUN_DIR [--first I] [--count N] [--option KEY=VALUE ...]`: read the
  sequence natively, run the pipeline, write the run folder.
- **Native readers** (in `slamlab_eval` / `slamlab-eval`, beside the PNG readers): TUM's
  `rgb.txt`/`depth.txt` and the camera table, or a TUM-format folder's own `camera.txt`
  (model, intrinsics, image size, depth scale) in place of the table, with ground truth
  optional: the calibration side track's export (decided 2026-10-05; the Python reader,
  `eval.tum.read_sequence`, gains the same). The file is plain text, since nothing native
  reads JSON. EuRoC's `data.csv` and `sensor.yaml` (the Python reader's regex parse,
  mirrored). Ground truth stays Python's: the programs never
  score a run. Held to Python's readers on shared fixture sequences in `tests/fixtures/eval/`.
- **Native run writer** (`eval::runs` / `slamlab_eval::runs`): `run.json`, `trajectory.txt`
  (each number shortest round-trip: C++ `std::to_chars`, Rust's float formatting, Python
  `repr`), `.npy` arrays (version 1.0, hand-written), `diagnostics.jsonl`. Held to a golden
  run folder (A9) and read back by Python's `read_run`; the files need not match byte for
  byte, their values must.
- **Python's side.** `slamlab.orchestration.vo.run(dataset, sequence, mode, out, *,
  backend, options)`: `python` runs the reference in-process; `cpp` and `rust` run the native
  program (found through `slamlab.backends`, as the extensions are), then read the run back.
  One interface, three backends, the native ones Python-free.

## 3. Parity and tests

- **Stage parity**, as rung 0: each stage function, on fixture states, in all three
  languages. Integer decisions (matches, culled indices, the keyframe decision) exact;
  poses and points to a tolerance; the RANSAC fallback seeded (PCG32, as rung 0).
- **Synthetic sequences** (`tests/fixtures/edge/`, generated): a textured box room rendered
  along a known trajectory through the exact image ops (a small ray-cast renderer in the
  generator, not in the package), written as TUM- and EuRoC-format folders with depth maps and
  rectified stereo pairs. Short (30-60 frames), so layer 1 stays fast.
- **Whole sequences**, each backend: completes the synthetic sequences in every mode; ATE
  under a stated bound against the known trajectory; the three backends' ATEs within a stated
  tolerance of each other. Native readers and writers: parity on the shared fixtures and the
  golden run folder.
- **Results** (not in layer 1): TUM fr1/xyz, fr1/desk, fr3/long_office_household (mono,
  RGB-D); EuRoC MH_01, V1_01 (mono, stereo). ATE and RPE per backend, Python on short
  subsequences (it is slow), set beside ORB-SLAM2/3's published numbers; rerun recordings
  from the run folders (`scripts/run_vo.py --rerun`).

## 4. Decisions (2026-10-05)

1. **No new runtime dependency** for the native writers: JSON and `.npy` are hand-written (the
   formats written are small and fixed), and options are CLI flags, so there is no native
   JSON reader. Rejected: nlohmann_json (C++) and serde_json (Rust) in the orchestration
   programs.
2. **Finding the native programs.** C++: scikit-build installs `slamlab_vo` into the package
   (`slamlab/bin/`); Rust: `setup_slamlab.sh` and `check.sh` build `slamlab-vo` with cargo,
   and `backends` finds it in `rust/target/release/`. Rejected: a PATH lookup, fragile
   across envs.
3. **The window size and the thresholds' defaults**: ORB-SLAM's where they exist (named in
   `edge.Options`), N = 10 keyframes for the window. Tuned only on the synthetic sequences
   and one TUM sequence, reported, not chased per sequence.

## 5. Commit plan

1. `feat(foundations)`: guided matching and the feature grid; the level map; H-RANSAC's rank rule.
2. `feat(edge)`: the map and frames (state, its crossing).
3. `feat(edge)`: initialisation, monocular and from depth.
4. `feat(edge)`: tracking: prediction, projection matching, refinement, the fallback.
5. `feat(edge)`: mapping: keyframes, triangulation, fusion, local BA, culling.
6. `feat(edge)`: the pipeline per mode, on the synthetic sequences.
7. `feat(eval)`: native TUM and EuRoC readers; the native run writer; the golden run folder.
8. `feat(orchestration)`: the native programs, Python's `vo.run`, `scripts/run_vo.py`.
9. `docs`: results on TUM and EuRoC; the edge note; CHANGELOG; VERSION (0.3.1.1 -> 0.3.2.0).

Each commit lands its stage in all three languages with its fixtures and layer 1 green; the
panel runs once on the finished PR; offline CI gates the merge.
